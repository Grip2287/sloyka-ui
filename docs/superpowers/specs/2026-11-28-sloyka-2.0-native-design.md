# Sloyka 2.0: нативные компоненты (HTML + CSS) рядом с React

Решения владельца (2026-11-28):
- формат: HTML + CSS; у компонента с поведением — свой маленький JS-файл, общего `native.js` нет;
- версия: 2.0.0;
- кнопка «Меню аккаунта» с ветки `feat/menu-trigger` входит в выпуск.

## Что получает пользователь

1. **Два способа собрать сайт из одних и тех же компонентов.**
   - **React:** `import { Button } from 'sloyka'`, работает как в 1.x.
   - **Нативный:** HTML-разметка с классами `sl-*`, файл `sloyka/styles.css` и, если у компонента есть поведение, его скрипт `sloyka/native/<компонент>.js`. Вид у обоих способов одинаковый, потому что CSS общий.
2. **Нативная разметка не пишется руками.** Её генерирует `renderToStaticMarkup` из тех же примеров, что показывает Storybook. Поэтому она совпадает с React, это гарантирует сама генерация, а тест проверяет, что готовые файлы не устарели.
3. **Скрипты по компонентам** `sloyka/native/<компонент>.js` — только у тех, где есть поведение: modal (открыть `data-sl-open="id"` / закрыть `data-sl-close`, Esc, затемнение, фокус), menu (кнопка, Esc, клик снаружи), theme-toggle + theme-head (тема без мигания), toast (`window.slToast.ok('…')`), group (свернуть), tooltip, segmented, compose (событие `sl-send`), shell (меню на телефоне; без JS работает через `#sl-nav`), window (закрыть). Каждый файл самостоятельный: без импортов, подключается `<script src>` или копируется в проект; подключать только нужные. Disclosure, поля, ссылки, формы — без JS. Свой JS сайта — только обработчики событий (данные, отправка, `addEventListener`), не вид.
4. **Справочник для агентов** `agents/native-components.md`: для каждого компонента 01–24 — HTML каждого варианта и data-атрибуты поведения. Машиночитаемый вариант — `native/components.json`. Готовые фрагменты лежат в `native/*.html`.
5. **`sloyka-check` проверяет и `.html`:**
   - `native-unknown-class`: класс `sl-*`, которого нет в `styles.css`;
   - `native-own-class`: свой класс или `id`-стиль у элемента внутри разметки Sloyka;
   - `native-no-inline-style`: атрибут `style`;
   - `native-no-style-tag`: `<style>`, который трогает `.sl-*`;
   - `native-js-markup`: в `.js` сайта — `innerHTML` или `className` с `sl-*`.

   Такие нарушения исправляют фрагментом из справочника.
6. **Выбор способа для ИИ-агентов** (`agents/sloyka.md`, скиллы, GUIDE, `AGENTS.md`). Нативный способ выбирается, если в запросе:
   - есть слово **«Предикат»** в любой форме: предикат, предиката, предикату и т. д., без учёта регистра;
   - или прямо сказано «только HTML и CSS», «без React», «нативные компоненты».

   Пример: «я хочу написать модуль для предикат. Создай мне админ панель используя библиотеку sloyka» — агент понимает, что пишет модуль для Предиката, и берёт только нативные компоненты. Во всех остальных случаях — React. Если в проекте уже есть React или `.html` на Sloyka, агент продолжает тем же способом.
7. **Новый компонент — сразу в двух вариантах.**
   - `npm run new:component -- <Name> <NN>` создаёт:
     - React-компонент с `defineMeta`;
     - CSS;
     - историю (story) с примерами;
     - нативный пример и, если нужно поведение, заготовку скрипта `src/native/<компонент>.js`;
     - тест.
   - Тест `native-coverage`: у каждого компонента из `components.json` есть нативные фрагменты, иначе сборка падает.
   - Правило записано в `AGENTS.md` библиотеки.
8. **Storybook:** панель «Код» у каждого примера, две вкладки:
   - **React** — исходник примера;
   - **HTML** — нативная разметка этого же примера, собранная из `renderToStaticMarkup`, со строками подключения `styles.css` и скрипта компонента (если он есть) и с текстом самого скрипта.

   Кнопка «Копировать» в обеих вкладках.
9. **Пример `examples/native`:** админ-панель на чистом HTML. Устроена так же, как `examples/vite`, включая модальное окно «Добавить пользователя» с 4 полями. Сборка — `sloyka-check .`.
10. **Кнопка «Меню аккаунта»** (вливание `feat/menu-trigger`). Новые эталоны скриншотов — только после того, как владелец одобрит скриншоты.

## Совместимость

React-API 1.x не меняется. 2.0.0 — из-за нового способа сборки и новых правил для агентов. Заметки выпуска объясняют, как выбрать способ.

## План

1. **N1. Генератор нативной разметки.** `scripts/gen-native.js` (через vite-node или tsx) берёт примеры из `src/native/samples.tsx` — по одному на каждый вариант компонента. Он выдаёт `native/*.html`, `native/components.json` и `agents/native-components.md`. Тесты проверяют актуальность и покрытие всех компонентов.
2. **N2. Скрипты компонентов.**
   - По файлу на каждый интерактивный компонент (`src/native/*.js`), в пакет — папкой `native/`.
   - Тесты в jsdom: те же сценарии, что у React.
3. **N3. `sloyka-check` для `.html`/`.js`:** правила, тесты, подсказки.
4. **N4. Storybook:** панель «Код» (React / HTML).
5. **N5. `new:component` и `AGENTS.md`.**
6. **N6. Влить `feat/menu-trigger`** и добавить нативный вариант меню.
7. **N7. Документация:**
   - `agents/sloyka.md`: выбор способа, «Предикат», пример;
   - `GUIDE`, `README`, скиллы, `PROMPTS`.
8. **N8. `examples/native`:** проверка в браузере.
9. **N9. Выпуск 2.0.0.**
   - changeset major и заметки: способы сборки, «Предикат», пример запроса, Storybook «Код».
   - Скриншоты владельцу, эталоны, `test:all`.
   - push и публикация — только по команде владельца.
