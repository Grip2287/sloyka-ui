# Sloyka 1.0: React-only, закрытые компоненты, проверка при сборке, публичный пакет

Дата: 2026-11-26. Статус: на согласование. Заменяет HTML-часть дизайна 0.1.x (`_team/docs/2026-11-26-sloyka-ui-library-design.md`); визуал, токены, шаблоны и референсы остаются.

## Зачем
Сайты и панели собираются на React (Vite или Next.js) **только из компонентов Sloyka**. Разработчик (и Claude по его запросу) комбинирует готовые компоненты и наполняет их данными, но не меняет их вид и устройство. Владелец меняет компоненты централизованно → выпуск → сайты обновляются после пересборки.

## Решения пользователя
- Только React. HTML-вариант (классы `sl-*` руками, веб-компоненты `<sl-*>`) **убираем** из публичного API.
- Компоненты закрыты: собирать можно **только** из них. Свои компоненты рядом **пока нельзя**.
- Строгость: закрытый API **+** проверка при сборке **+** подсказки в редакторе (ESLint + Stylelint) — оба способа.
- Работать должно и в **Vite**, и в **Next.js**.
- Репозиторий и пакет становятся **публичными** (владелец подтверждает: личная разработка, можно выкладывать). Текущий репозиторий `Grip2287/sloyka-ui` переводится в публичный, а не создаётся новый.
- Подробная инструкция: правила, где что лежит; в каждом выпуске — что добавлено и где лежит.

## Цели
- 24 группы (01–24) как React-компоненты с официальными номерами; каркас `Shell`.
- Закрытый API: только описанные props, без `className`/`style`/`...rest`; фиксированные значения вариантов; контейнеры принимают только компоненты Sloyka.
- `sloyka-check` (CLI) — обязательная проверка перед сборкой; `eslint-plugin` и `stylelint`-конфиг — те же правила в редакторе. Общий список правил в одном модуле.
- Работа в Vite и Next.js (App Router и Pages Router, серверная отрисовка без ошибок).
- Storybook на React: те же истории, песочницы, «Мой шаблон», «Все шаблоны», референсы.
- `docs/GUIDE.md` + автоматическое «что нового и где лежит» в каждом выпуске.
- Публичный пакет на npmjs.com.

## Не цели
- Секции лендинга и блоки магазина (отдельный будущий этап).
- Собственные компоненты разработчика внутри Sloyka (запрещено правилами).
- Поддержка HTML-использования и старого 0.1.x API (0.1.x остаётся в истории, не развивается).
- Vue/Svelte.

## Анти-цели
- Компонент, который можно перекрасить через props или `className`.
- Проверка, которая ругается на законный код (ложные срабатывания на свои страницы, роутинг, данные).
- Отличие вида React-компонента от одобренных скриншотов.
- Ошибки гидрации в Next.js.

## Подходы (рассмотрены)
| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **А (выбран)** | React-компоненты поверх **существующего CSS** (`@layer sl.*`, токены, шаблоны); поведение переписано на React (без веб-компонентов) | Вид остаётся пиксель-в-пиксель, шаблоны/референсы работают как есть, нет второй копии стилей | CSS-классы `sl-*` остаются внутренней деталью — нужно запретить их использование снаружи (это и делает проверка) |
| Б | CSS-in-JS / CSS-модули внутри компонентов | Классы не видны снаружи | Ломает шаблоны и референсы (они на переменных и классах), проблемы с серверной отрисовкой, переписывать все стили |
| В | Обёртки над веб-компонентами `<sl-*>` | Меньше кода сейчас | Пользователь убирает HTML-часть; в Next.js веб-компоненты сложнее с SSR и событиями |

Проверка: выбрано **CLI + ESLint/Stylelint** (пользователь: «сразу и то и то»).

## Решения, принятые мной (можно поправить)
- **Пакет:** `sloyka` на npmjs.com (имя свободно на 2026-11-26), версия **1.0.0** (ломающее изменение API). Лицензия **MIT**. Для публикации нужен аккаунт npm владельца и токен `NPM_TOKEN` в секретах репозитория (делает владелец).
- **Входы пакета:** `sloyka` (компоненты), `sloyka/styles.css` (все стили, один импорт), `sloyka/templates/*.css`, `sloyka/check` (CLI `sloyka-check`), `sloyka/eslint` (плагин), `sloyka/stylelint` (конфиг). Внутренние пути закрыты полем `exports`.
- **Язык:** TypeScript; в пакет — JS (ESM) + `.d.ts`. Поддержка React 18.3 и 19 (`peerDependencies`), ноль runtime-зависимостей кроме React.
- **Next.js:** интерактивные компоненты помечены `'use client'`; статичные (Tag, Status, Card…) — серверные; ни один не читает `window` при отрисовке.
- **Иконки:** `<Icon name="plus" />` + prop `icon="plus"` у компонентов (список имён — тип TS).
- **Уведомления:** `<ToastProvider>` в корне + хук `useToast()`; `toast.ok/warn/crit/info`.
- **Тема:** `<ThemeProvider defaultTheme="system">` + `<ThemeToggle />`; `ThemeScript` для `<head>` (без мигания, и в Next.js).
- **Состав контейнеров (что можно вкладывать):** задаётся таблицей в коде (`allowedChildren`), из неё же строятся предупреждения в dev, правила проверки и справочник.

## Правила проверки (одни и те же в CLI, ESLint, Stylelint)
1. JSX: запрещены нативные интерактивные и раскладочные теги (`button, input, select, textarea, dialog, a, form, table, div, span, section, header, nav, main, h1–h6, p, ul, li, img`) — используйте компоненты. Разрешены: `html, head, body, meta, link, script, title` (корневой layout Next.js), фрагменты.
2. JSX: на компонентах Sloyka запрещены `className`, `style`, `dangerouslySetInnerHTML`.
3. Импорт только из `sloyka`, `sloyka/styles.css`, `sloyka/templates/*`. Глубокие импорты запрещены.
4. CSS/SCSS/модули: запрещены селекторы с `.sl-` и переопределение `--sl-*`, кроме подключения шаблона (`@import 'sloyka/templates/…'`).
5. Запрещены свои React-компоненты, рендерящие нативные теги (следует из п.1); компоненты-«страницы» из компонентов Sloyka — разрешены.
6. Исключения: файл `sloyka.allow.json` в корне проекта (список путей/правил) — создаёт только владелец, проверка печатает каждое исключение. По умолчанию пусто.
Каждое нарушение: файл:строка, правило, чем заменить («`<button>` → `Button` (01)»).

## Уточнения после проверки строителем (мои решения)
1. **Ссылки, роутинг, картинки, формы.** У `Button`, `Nav.Item`, `Row`, `LinkCard`, `Menu.Item`, `Tile` есть `href` и `linkAs` (компонент роутера: `next/link`, `Link` из react-router) — без него рендерится обычная ссылка. Добавляются компоненты **`Link`** (текстовая ссылка, тот же `linkAs`), **`Image`** (`src`, `alt` обязателен, `width`/`height`, `fit: cover|contain`, `radius: none|sm|md|lg`) и **`Form`** (`onSubmit`, `action`, `method`; внутри — любые компоненты Sloyka). Нативные `<a>`, `<img>`, `<form>` остаются запрещены.
2. **Раскладка.** `Stack`: `gap` = `1…8` (шкала токенов), `direction: column|row`, `align`, `justify`, `wrap`. `Grid`: `columns` = `1|2|3|4|auto` (auto = заполнять колонками от `min: sm|md|lg` = 200/280/360px) + `gap`; на телефоне колонки сами переходят в одну. **`Page`**: ширина контента `narrow|default|wide|full`, отступы по токенам; фон страницы — тема. Произвольных пикселей нет.
3. **Данные и текст.** Строки и числа можно класть в любой компонент, где ожидается текст; результат `.map()` — как обычные дети. `Table`: `columns: [{ key, title, align?, width?: 'auto'|'min', render?: (row) => узел Sloyka }]`, `rows`, `rowKey`, `empty` (текст/узел), `onRowClick`; сортировки в 1.0 нет. `Text`: `as`-уровни `page|section|title|body|small|caption`, `tone: default|muted|ok|warn|crit`, внутри можно `Text` с `weight="strong"` и `Link`. **Проверка вложений:** в dev — во время работы (у каждого компонента внутренняя метка; чужой элемент → предупреждение в консоли с перечнем разрешённого); статически CLI/ESLint проверяют только правила 1–4 (нативные теги, `className/style`, импорты, CSS).
4. **Поведение = текущее, плюс React-управление.** Сохраняются: фокус-ловушка и возврат фокуса в `Modal`, закрытие Esc/фоном (с проверкой «нажали и отпустили на фоне»), меню телефона (`Shell`), клавиатура в `Segmented` (←/→), ARIA как сейчас. Каждый интерактивный компонент — и управляемый (`value`/`onChange`, `open`/`onOpenChange`), и неуправляемый (`defaultValue`, `defaultOpen`).
5. **Где живут `.sl-*`.** Это внутренняя деталь пакета: `styles.css`, `templates/*.css` и референсы остаются CSS и подключаются целиком. Правило 4 применяется только к коду сайта; Storybook и сам пакет проверке не подлежат. HTML-часть 0.1.x удаляется из `main`; её состояние сохраняется тегом `v0.1.0` (и пакетом `@grip2287/sloyka@0.1.0`).
6. **Что считается «своим компонентом».** Разрешены любые функции-компоненты, которые возвращают **только** компоненты Sloyka (страницы, обёртки со своим состоянием, загрузкой данных, `useToast`). Запрещены те, что возвращают нативные теги — это ловит правило 1. CLI разбирает `.js/.jsx/.ts/.tsx` (`.mdx` и прочее пропускает с предупреждением) парсером `@babel/parser` — это **зависимость только CLI**, в код компонентов она не попадает.
7. **Эталон вида.** Текущие одобренные скриншоты историй 0.1.x (`tests/e2e/__screenshots__/win32`) — эталон: React-истории тех же примеров должны совпасть с ними в Playwright с допуском `maxDiffPixelRatio 0.01`; расхождения показываются владельцу.
8. **Имя и проверка в Next.js/Vite.** Имя `sloyka` перепроверяется перед первой публикацией; если занято — `@grip2287/sloyka` на npmjs.com (аккаунт `grip2287`). В репозитории два примера-приложения **`examples/vite`** и **`examples/next`** (App Router), собираются в CI с `sloyka-check` (и с намеренно «плохим» файлом в отдельной проверке, чтобы убедиться, что сборка падает).
