# Sloyka: страницы только из компонентов

Sloyka — закрытый набор React-компонентов. Ты **собираешь** страницы из них и не меняешь их вид. Полный список компонентов, props и допустимых значений — `components.md` рядом с этим файлом (или `node_modules/sloyka/components.json`). Инструкция для людей — `docs/GUIDE.md` в репозитории.

## Жёсткие правила
- **Никаких своих тегов** в коде сайта: `div`, `span`, `button`, `table`, `h1`, `p`, `a`… Исключение одно: `<html>`, `<head>`, `<body>` в `app/layout.tsx` и `app/global-error.tsx` (Next).
- **Никаких `className`, `style`, `dangerouslySetInnerHTML`** у компонентов Sloyka, никаких spread-пропсов `{...props}` на них.
- **Никакого CSS** для `.sl-*`, никаких `styled-components`/`@emotion`, никаких импортов из `sloyka/dist/…`.
- Значения `variant`, `size`, `tone`, `columns`… — **только из списка** в `components.md`.
- Можно: свои функции-компоненты, которые возвращают только компоненты Sloyka; любые тексты, данные, логика, состояние, загрузка данных.
- **Нет нужного компонента — не выдумывай** и не собирай из тегов. Скажи пользователю: «В Sloyka нет компонента для X. Предлагаю попросить владельца библиотеки добавить его». Пока его нет — ближайший существующий компонент или пропусти блок.

## Порядок работы
1. **Запрос → номера компонентов.** Разложи задачу пользователя на группы 01–24 и покажи план в одну-две строки: «каркас — 24 Shell/Nav, 16 Topbar; список объектов — 06 Card в Grid; журнал — 13 Table; добавление — 21 Modal с 02 Field; результат — 22 useToast».
2. **Подключение** (один раз): `npm i sloyka@<точная версия>`; `import 'sloyka/styles.css'` в корне; `ThemeProvider` и `ToastProvider` вокруг приложения; в Next — `<ThemeScript />` в `<head>` и `suppressHydrationWarning` на `<html>`.
3. **Сборка страниц** из компонентов по плану. Ссылки в Next/react-router — через `linkAs={Link}`.
4. **Проверка:** `npx sloyka-check src` (или папка `app`) — ноль нарушений. Добавь в проект `"prebuild": "sloyka-check src"`, если его нет. Затем сборка проекта. Нарушение исправляй заменой на компонент из совета, а не исключением.
5. Исключение в `sloyka.allow.json` — только с прямого согласия пользователя и с причиной.

## Шаблоны («сделай по шаблону 1»)
Шаблон — это тема и размеры, собранные пользователем в Storybook. Файл `node_modules/sloyka/templates/template-N.css`. Подключи **после** стилей: `import 'sloyka/templates/template-N.css'`. Нет файла — обнови пакет; нет и там — спроси пользователя. Поверх шаблона ничего не переопределяй.

## «Обнови sloyka»
1. Сначала покажи, **что нового и где лежит**: раздел выпуска в `CHANGELOG.md` нового пакета (Добавлено / Изменено / Удалено / Нужно поправить в сайтах). Подожди согласия.
2. Поменяй версию в `package.json`, `npm i`.
3. `npx sloyka-check src` и сборка — исправь то, что стало нарушением (пункты «Нужно поправить»).
4. Откат — вернуть прежнюю версию.

## Лендинги и магазины
В Sloyka нет блоков лендинга (hero, цены, отзывы) и магазина (карточка товара, корзина). Не верстай их из тегов в проекте на Sloyka: скажи пользователю, каких компонентов не хватает, и предложи запросить их у владельца библиотеки.

## Проверь перед сдачей
- `sloyka-check`: 0 нарушений; сборка проходит.
- Обе темы (переключатель `ThemeToggle`) и ширины 390, 1024, 1440: нет горизонтальной прокрутки и обрезанного текста.
- У иконочных кнопок есть `aria-label`; статус никогда не передаётся только цветом.
